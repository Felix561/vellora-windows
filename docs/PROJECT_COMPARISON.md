# Vellora and other dictation projects

Reviewed on **2026-10-04** for the private publication review. This is a focused comparison of public documentation and selected source files, not a security certification or a transcription benchmark. No peer application was installed, and no recordings or personal data were submitted to a peer service.

The relevant projects are **OpenWhispr** and **Handy**. **Wispr Flow** is a commercial product with free and paid plans; it is useful as a presentation reference, but its official product site does not establish an open-source desktop repository. The name "Open Whisper Flow" is ambiguous. This review uses the OpenWhispr repository previously supplied by the maintainer rather than assigning a guessed repository to that name. See the [Wispr Flow product site](https://wisprflow.ai/) and [pricing](https://wisprflow.ai/pricing).

## What differs

| Project | License and Windows delivery | Product scope and processing | Relevance to Vellora |
| --- | --- | --- | --- |
| **Vellora** | Public MIT source beta for Windows; installer release deferred | Windows dictation through the user's OpenAI API key, optional text cleanup, local text history, tray controls, click-through indicator, Notebook and Windows Classic appearances | A focused client with a smaller feature and operational surface. No offline engine, Vellora account, or model-download manager. OpenAI usage is billed separately. |
| **[OpenWhispr](https://github.com/OpenWhispr/openwhispr)** | [MIT](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/LICENSE); Windows Electron installer and other desktop platforms | README advertises local and cloud dictation, multiple providers, meeting transcription, notes, assistants, and team features | A broader product. Its [README](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/README.md) and dedicated documentation make user setup and downloads easy to find. This review did not verify every advertised feature or its privacy claims. |
| **[Handy](https://github.com/cjpais/Handy)** | [MIT](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/LICENSE); Tauri Windows builds and other desktop platforms | README centers on local transcription with model choice and voice activity detection; source also contains optional post-processing settings | The closest architectural reference for a Tauri/Rust client. Its local-model workflow is a different product choice, not a small missing setting in Vellora. See its [README](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/README.md). |

MIT licenses on these repositories do not establish that every bundled dependency, model weight, font, image, or native helper has the same license. Any future reuse needs attribution and a component-specific license review. This preparation borrowed ideas only; it did not copy peer source code, screenshots, logos, or README wording. A future GPL/AGPL component cannot simply be relabeled MIT.

## Presentation ideas worth applying

These are editorial recommendations for Vellora, informed by the user paths in the peer READMEs. They do not imply equivalent product scope.

| Idea | Effort | Why it helps |
| --- | --- | --- |
| State the concrete purpose first: Windows dictation with an OpenAI API key | Small documentation edit | A reader can identify the operating system, provider, and billing relationship immediately. |
| Explain Vellora's focused appeal: two appearances, recoverable text, tray dictation, and inspectable client code | Small documentation edit | These are useful differences already implemented; the project does not need a long competitive feature list. |
| Keep the two dashboard screenshots near the top, with the remaining synthetic images collapsed | Already available | Shows the app without publishing personal history; a gallery is sufficient before a demo video exists. |
| Keep user installation and first dictation separate from contributor commands | Small documentation edit | Users can reach their first transcript without reading Rust tooling instructions. |
| Put paid cloud usage and local-history limits alongside setup/privacy links | Small documentation edit | Avoids suggesting that an MIT app makes OpenAI usage free, or that local key storage makes cloud transcription offline. |
| Treat source publication and public installer distribution as separate review decisions | Small documentation/release edit | A readable source beta can be approved while clean-install, signing, and hardware checks remain explicit installer gates. |

Do not adopt peer slogans about entirely local processing, universal app compatibility, accuracy, or speed. Vellora's cloud behavior and paste limits should remain visible. The public source-beta status and deferred installer release must remain accurate. A public download link should only be added when an approved artifact actually exists.

## Technical lessons from inspected code

The following findings come from specific files, rather than feature lists or repository popularity.

| Inspected evidence | What it teaches | Vellora status and sensible next step |
| --- | --- | --- |
| OpenWhispr's [clipboard regression tests](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/test/helpers/clipboardRestore.test.js) cover rich-format restoration, intervening writes, serialization of paste/restore operations, and native helper arguments | Paste correctness is a state/race problem, not just a successful keyboard injection | [Vellora's clipboard code](../src-tauri/src/clipboard.rs) uses foreground-window checks and clipboard sequence checks, but preserves plain text only. Prioritize a real Windows clipboard/focus test matrix. Rich-format preservation is a later feature requiring more native work. |
| OpenWhispr's [paste recovery test](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/test/helpers/audioManagerPasteRecovery.test.js) distinguishes confirmed permission recovery from general paste errors | Preserve useful text while keeping error categories honest | Vellora already exposes transcript recovery and copy/manual paste. Native tests should check that a failed paste retains text and never reports that the destination accepted it merely because `SendInput` succeeded. |
| Handy's [device enumeration](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/src-tauri/src/audio_toolkit/audio/device.rs) exposes input names/default status; its [onboarding](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/src/components/onboarding/Onboarding.tsx) includes model download/verification progress | A microphone picker and sound check can make hardware failures easier to explain | Vellora's local availability check is intentionally narrower. Add an input picker/live level check later if users need it; test disappearing devices and avoid including device names in shared diagnostics. Peer model-download onboarding is unnecessary for a cloud-only app. |
| Handy's [model-download tests](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/src-tauri/src/managers/model/download/tests.rs) use temporary directories and local HTTP fixtures for hashes, interrupted transfers, ranges, and cancellation | Network failure behavior can be tested without contacting a paid service | The same testing technique fits Vellora's [OpenAI client](../src-tauri/src/openai.rs): bounded retry/deadline, malformed response, and failure recovery checks. Vellora does not need a model downloader to use this lesson. |
| Handy has [Playwright CI](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/.github/workflows/playwright.yml), but the inspected [app spec](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/tests/app.spec.ts) checks HTTP 200 and HTML/body structure | The presence of browser tooling is not proof of broad UI coverage | Vellora already has behavioral [frontend regressions](../tests/frontend). A later rendered-browser suite should check actual navigation, both themes, focus, overflow, and setup flows; merely copying a page-load test adds little confidence. This finding concerns that spec only, not all Handy testing. |
| Handy's [release workflow](https://github.com/cjpais/Handy/blob/73ab851c2b6242283759a4c101b60f0ece132f08/.github/workflows/release.yml) is manually triggered, creates a draft, requests signed binaries, and builds releases without a restored Rust cache | Publication can be deliberate and reviewable | Vellora's [CI](../.github/workflows/ci.yml) currently produces private review artifacts. Prepare release notes, checksums, and an explicit maintainer approval step before public distribution. This review did not cryptographically verify a downloaded peer installer. |
| OpenWhispr's [release workflow](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/.github/workflows/release.yml) validates tag/package agreement and runs quality, audit, and database-backed tests before build jobs | A release should enforce consistency and avoid silently skipped important tests | Vellora has synchronized version references and CI checks. Preserve those release gates without importing the peer's multi-platform builds or its much larger helper download chain. |
| OpenWhispr's [security policy](https://github.com/OpenWhispr/openwhispr/blob/85b01157f597036ad88c4901cea8d71ab8e46a43/SECURITY.md) names private reporting, renderer/IPC risks, credentials, and native helpers | Security documentation should describe actual trust boundaries and a private reporting route | Vellora should keep its policy specific to Tauri commands, Windows key storage, OpenAI requests, local history, and paste. Avoid response deadlines that a single maintainer cannot support. Its peer's supported-version table still names 1.7.x while the inspected package names 1.10.2, so polished projects also need documentation maintenance. |

## What Vellora already has

The inspected Vellora code is a reasonable basis for a focused Windows source beta: a Rust backend, React/TypeScript UI, CPAL recording, SQLite history, Windows Credential Manager key storage, constrained help destinations, and a restrictive production content-security policy. The [OpenAI request layer](../src-tauri/src/openai.rs) uses a fixed provider endpoint, bounded timeouts, and disabled redirects. The [audio layer](../src-tauri/src/audio.rs) caps recording duration/upload size. [Credentials](../src-tauri/src/credentials.rs) and [history](../src-tauri/src/history.rs) are separate, with local text history remaining unencrypted as disclosed in [privacy documentation](PRIVACY.md).

These are observations about the implementation, not proof that every driver, application, display scale, or failure sequence works. Automated regression tests and dependency/secret scans complement the clean-account installation, microphone, shortcut, clipboard, paste, and native accessibility checks; they do not replace them. See the current [audit](AUDIT.md), [GUI test plan](GUI_TESTING.md), and [roadmap](ROADMAP.md) for validation status.

## Recommendation

Open sourcing Vellora is a reasonable choice once the publication review resolves ownership, license/notice, history/privacy, and reporting checks. It lets users inspect the client, reproduce builds, and contribute Windows fixes. Its current appeal is a focused, transparent OpenAI client with distinctive appearances, rather than feature parity with a large meeting/agent suite or an offline engine.

There is no need to add another operating system, accounts, cloud sync, meeting recording, local models, an updater, or streaming before publishing the source. Those changes enlarge testing, privacy, maintenance, and distribution obligations. The highest-value follow-up is evidence for Windows installation and paste behavior, followed by microphone selection if real user reports justify it. A public installer deserves its own approval after those native checks.
